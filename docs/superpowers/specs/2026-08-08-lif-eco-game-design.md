# LIF 生态游戏（喂食-产出-淘汰-繁殖）设计

## Context（背景与动机）

现有 STDP 进化系统（`evolve.py` + `snn.py`）已跑通，最优 acc 69.4%，但训练方式与用户的原始设想不同：
- 现有系统：权重不遗传，个体一生中用 STDP 自学，离线评估适应度，无性分裂繁殖。
- 用户理想：**权重随机出生、随有性繁殖遗传**，一生不做任何学习/计算；用"喂食数字 → 产出数字"的游戏式循环做淘汰与繁殖。

本设计实现用户理想的版本：一个**可视化生态游戏**，生物体吃数字、吐数字、对得上就存活并繁殖（吃对越准繁殖越多），权重作为基因在有性繁殖中交叉变异遗传。

## 核心决策（已与用户对齐）

| 维度 | 决策 |
|---|---|
| 形态 | **可视化游戏界面**（网页动画，Python 后端计算 + 单文件 HTML 播放事件流） |
| 产出机制 | 最后一层为 **10 个 LIF 产出神经元**（对应数字 0-9），喂食后取累计脉冲最多者为"吐出的数字"；产出层权重也在基因里，随繁殖交叉/变异 |
| 一生行为 | 无 STDP、无学习、无阈值自适应——权重出生即固定，只有纯 LIF 放电 + WTA 侧抑制 |
| 适应度 | 当天吃对率（喂 K 个数字，产出与喂入一致的占比） |
| 繁殖 | **有性繁殖**：子代权重逐权重 50/50 取父/母 + 全体加微小高斯噪声 + 千分之一权重大幅突变 |
| 淘汰 | 每天按吃对率排序，底部 30% 饿死；生物体有寿命与劣绩衰减（生态压力） |
| 结构 | 第一版固定单隐藏层（784→100→10）；"多层"作为后续扩展 |
| 现有系统 | STDP 进化系统保留不动，独立共存 |

## 架构总览

```
eco_engine.py   生态引擎：喂食、产出、判定、淘汰、有性繁殖、事件流（纯计算，无 UI）
eco_server.py   本地小服务：引擎预跑若干代缓冲事件，向网页推送
eco_game.html   单文件前端：Canvas 培养皿动画 + 控制条 + 统计曲线 + 个体解剖视图
```

数据流：`eco_server` 预跑引擎 N 代 → 缓存事件序列（喂食/产出/死亡/繁殖）→ 前端按播放节奏重放动画 → 用户可暂停/调速/手动喂食 → 手动喂食触发引擎即时计算该数字的产出并回传。

**关键隔离**：引擎是纯函数式模拟，产出标准化事件 JSON；前端只渲染事件，不含任何神经计算。两者通过事件流解耦，保证动画流畅不阻塞。

## 组件设计

### 1. `eco_engine.py` — 生态引擎（纯计算）

**生物体 Genome**（可序列化 JSON）：
- `hidden: list[float]` — 100×784 输入→隐藏层权重（展平）
- `readout: list[float]` — 10×100 隐藏→产出层权重
- `name`, `born_gen`, `age`, `parents: (nameA, nameB)`
- 权重出生时在 [0, 0.1] 均匀采样后按列归一化到固定 L2 范数（保证 LIF 动力学不爆/不哑），列归一化后写入基因

**喂食（forward）**：给一个 digit（784 像素）→
1. 泊松编码（复用 `snn.py` 的 `_poisson`，`spike_gain=0.6`，T=200）
2. 隐藏层逐样本跑 LIF（纯放电 + WTA，**无 STDP、无 homeostasis**）
3. 隐藏层脉冲喂给产出层，累计 10 个产出神经元的脉冲数
4. 产出 = `argmax(累计脉冲)`；产出层不发放任何数字 → 计为"没吐出"（特殊标记）

**一天（generate_day）**：
1. 从 MNIST 抽 K=50 个数字作食物（0-9 均衡）
2. 每个存活生物体逐个吃下 50 个数字，算吃对率
3. 排序 → 底部 30% 死亡
4. 年龄+1；若连续多天无改善或年龄超上限 → 生态压力死亡
5. **繁殖**：吃对率按排名转成繁殖名额（轮盘赌，吃对越准越可能被选中当亲本）；每次繁殖取双亲做有性繁殖产生 1 子代；种群有上限 N（如 60），超出则杀掉最弱者

**有性繁殖（crossover）**：子代权重 = 对每个权重：
- 50% 概率取父，50% 取母（逐权重伯努利）
- 全部加 N(0, σ=0.01)
- 千分之一权重被大幅重置为随机值

**事件输出**：每步产出事件 dict：`{type: feed|produce|death|birth|day_end, ...}`，供前端播放。

### 2. `eco_server.py` — 本地服务

- Python `http.server` 静态托管 `eco_game.html` + `/events` 接口
- 启动时后台线程用引擎预跑 20 代，把事件序列缓存成 JSON
- `/events?from=N` 增量拉取；`/feed/<index>` 手动喂食即时计算并回传产出

### 3. `eco_game.html` — 前端动画（原生 JS + Canvas）

- **培养皿网格**：每格一只生物体，显示吃进的数字、吐出的数字、吃对率、存活天数、✓/✗
- **动画**：喂食（数字落入）→ 产出（数字弹出）→ 判定（✓/✗）→ 死亡（变灰融化）→ 繁殖（双亲分出新个体）
- **控制条**：播放/暂停、速度、手动喂一个数字
- **点击生物体**：展开解剖视图——10 个产出神经元脉冲分布直方图、父母、家谱
- **统计曲线**：种群平均吃对率、最优吃对率、存活数量随"天"演化
- 风格延续 snn_demo.html；单文件无外部依赖

## 诚实预期

纯随机权重 + 有性繁殖交叉在 78400 维实数权重空间直接搜解，是神经进化学中最难的一类问题（GA 对高维实数的搜索效率远低于 STDP 结构学习）。**预期**：
- 能演示真实的生态动力学：选择压推动种群吃对率先升后平、多样性演化、家谱结构
- 最终吃对率**大概率明显低于 STDP 系统的 69%**，甚至可能只略高于随机（10%）
- 目标是**生态游戏演示 + 诚实数字**，不追求超越 STDP

## 验证方案

- 引擎单测：喂食判定正确、繁殖权重继承比例符合 50/50±噪声、事件流完整
- 跑 50 代小种群：确认无崩溃、事件流可连续播放
- 前端加载 `eco_game.html`：动画播放、控制条、解剖视图可用
- 记录最终吃对率曲线，如实报告（若只达随机水平也如实说明）
